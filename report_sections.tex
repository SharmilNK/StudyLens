\section{Data \& Problem Setup}
\label{sec:data}

\subsection{Data Sources}

We collect lecture materials from two Duke University courses: Deep Learning (5 lecture sets) and Machine Learning (5 lecture sets), totaling 10 lecture topics. For each topic, three complementary source types are gathered:

\begin{itemize}
    \item \textbf{Slide decks} (PPTX): Instructor-authored slides containing structured content, figures, and key definitions.
    \item \textbf{Auto-generated transcripts} (TXT): YouTube auto-captions (identified by the \texttt{[Auto-generated by YouTube]} header) from recorded lectures, providing spoken explanations and elaborations.
    \item \textbf{Student notes} (TXT): Handwritten or typed notes capturing a student's interpretation of the material.
\end{itemize}

These three sources are complementary: slides offer structured definitions and visual cues, transcripts capture verbal explanations and examples, and student notes reflect how learners organize and internalize the material. Combining all three gives summarization models a richer and more complete picture of each lecture.

For evaluation, we prepare one human-written reference summary per topic, yielding 10 reference summaries used to compute ROUGE-L and BERTScore.

\subsection{Data Processing Pipeline}
\label{sec:pipeline}

Our processing pipeline converts raw lecture materials into clean, model-ready text through four stages: cleaning, chunking, embedding, and topic assignment. Figure~\ref{fig:pipeline} illustrates the full flow.

\paragraph{Stage 1: Cleaning.}
Each source type undergoes tailored preprocessing:
\begin{itemize}
    \item \textbf{Transcripts}: We remove the YouTube auto-caption disclaimer header (e.g., \texttt{[Auto-generated by YouTube]}), join fragmented caption lines, collapse extra whitespace, and strip filler words (\textit{um}, \textit{uh}, \textit{like}, \textit{you know}, \textit{sort of}, etc.). Noise lines matching common patterns (e.g., greetings, audio checks, Q\&A markers, break announcements) are removed. The first and last 50 lines are additionally trimmed if they match these noise patterns.
    \item \textbf{Student notes}: Line endings are normalized and runs of three or more blank lines are collapsed to two.
    \item \textbf{Slides}: Text is extracted from every slide in the PPTX file. Slide titles are identified via PowerPoint's placeholder index. Decorative symbols (\texttt{\#}, $\blacktriangle$, $\diamondsuit$, $\bigstar$, $\bullet$) are stripped to produce plain text.
\end{itemize}

\paragraph{Stage 2: Chunking.}
Cleaned text is split into chunks of approximately 200 tokens with one overlapping sentence between consecutive chunks. Chunks smaller than 30 tokens are discarded. We use the BART tokenizer (\texttt{facebook/bart-large-cnn}) for token counting. The chunking strategy varies by source type:
\begin{itemize}
    \item \textbf{Transcripts}: Sentence-level sliding window using NLTK \texttt{sent\_tokenize}. Sentences are greedily accumulated until the next sentence would exceed the chunk size limit, at which point the chunk is flushed and the last overlapping sentence carries over to the next chunk.
    \item \textbf{Student notes}: Split at blank lines (paragraph boundaries). Short adjacent blocks are merged; blocks exceeding the chunk size fall back to the sentence sliding window.
    \item \textbf{Slides}: Each slide serves as a semantic unit. Short adjacent slides are merged. Oversized slides are sub-chunked via the sentence sliding window.
\end{itemize}

\paragraph{Stage 3: Embedding.}
All chunks are embedded using \texttt{all-MiniLM-L6-v2}~\citep{reimers2019sentence}, a 384-dimensional sentence transformer trained on over one billion sentence pairs. Embeddings are L2-normalized so that cosine similarity reduces to a dot product. Processing uses a batch size of 32.

\paragraph{Stage 4: Topic Assignment.}
We define one query string per lecture topic (e.g., ``deep learning'', ``supervised learning''). Each query and each chunk are embedded with MiniLM. Cosine similarity is computed between all query--chunk pairs, and each chunk is assigned to the topic with the highest similarity score. Chunks whose best score falls below a relevance threshold of 0.35 are discarded as off-topic noise. The surviving chunks are concatenated per topic to produce one combined source file per lecture, which serves as the input to all summarization models.

The final output of the pipeline is a set of 10 topic-level source files, each merging slide content, denoised transcript text, and student notes into a single document ready for summarization.

\section{Experiments and Results}
\label{sec:results}

We evaluate StudyLens through four experiments, each designed to isolate one factor: model architecture, summarization strategy, output length, and the effect of fine-tuning. All experiments are run on the same 10 lecture topics and share a unified evaluation pipeline. Every model configuration is evaluated using three metrics---ROUGE-L F1, BERTScore F1, and NLI entailment---across all 10 topics.

\paragraph{Extractive Baselines.}
\textbf{Naive (first-5)} selects the first 5 sentences. \textbf{Naive (random-15)} randomly samples 15 sentences. \textbf{TF-IDF} ranks all input sentences by TF-IDF scores and selects the top 15.

\paragraph{Fine-Tuned Encoder--Decoder Models.}
We evaluate four pre-trained encoder--decoder models, each fine-tuned on a different summarization dataset:
\begin{enumerate}
    \item \textbf{BART-CNN}~\citep{lewis2020bart}: \texttt{facebook/bart-large-cnn}, 1,024-token context. Fine-tuned on CNN/DailyMail news articles.
    \item \textbf{Long-T5}~\citep{guo2022longt5}: \texttt{pszemraj/long-t5-tglobal-base-16384-book-summary}, 16,384-token context. Fine-tuned on BookSum for long-document summarization.
    \item \textbf{BART-SAMSum}: \texttt{philschmid/bart-large-cnn-samsum}, 1,024-token context. Fine-tuned on SAMSum dialogues, included because lecture transcripts contain conversational elements.
    \item \textbf{LED-arXiv}~\citep{beltagy2020longformer}: \texttt{allenai/led-large-16384-arxiv}, 16,384-token context. Uses Longformer attention, fine-tuned on arXiv papers.
\end{enumerate}
All four use sentence-aware greedy chunking and are evaluated under both \textit{concat} and \textit{final} strategies (see Experiment~2).

\paragraph{Instruction-Tuned LLM.}
\textbf{Qwen2.5-7B-Instruct}~\citep{qwen2025qwen25} has a 128K-token context window, processing full lectures in a single pass without chunking. We use 4-bit NF4 quantization via BitsAndBytes, greedy decoding, and a repetition penalty of 1.1. Output length is controlled by an \textit{output ratio} parameter (target tokens as a fraction of input length), swept across six values: 1\%, 3\%, 6\%, 9\%, 15\%, and 30\%.

\paragraph{Fine-Tuned LLM (Qwen2.5-7B-ft).}
We additionally fine-tune Qwen2.5-7B on our lecture summarization data at the 6\% output ratio. This model, denoted \textbf{qwen7b-ft}, uses the same inference setup as the base Qwen model but with weights adapted to lecture-style summaries.

\subsection{Evaluation Metrics}

We evaluate using three complementary metrics:
\begin{itemize}
    \item \textbf{ROUGE-L F1}~\citep{lin2004rouge}: Longest common subsequence between summary and reference, capturing surface overlap. Computed with stemming enabled.
    \item \textbf{BERTScore F1}~\citep{zhang2020bertscore}: Token-level cosine similarity using \texttt{roberta-large} embeddings with baseline rescaling. Long texts are chunked into 450-word segments, aligned pairwise, and averaged.
    \item \textbf{NLI Entailment Score}: Uses \texttt{cross-encoder/nli-distilroberta-base} to measure factual consistency. Each summary sentence is paired with the top-5 most similar source chunks (by Jaccard word overlap), and the maximum entailment probability is recorded. We report the average entailment score across all summary sentences.
\end{itemize}
We also compute a \textbf{composite score} as the mean of all three metrics, used for overall model ranking.

\subsection{Summary of Findings}

Four key findings emerge:
\begin{enumerate}
    \item \textbf{Instruction-tuned LLMs outperform all encoder--decoder models.} Every Qwen configuration outperforms all four fine-tuned encoder--decoder models (BART-CNN, Long-T5, BART-SAMSum, LED-arXiv) and both extractive baselines on composite score.
    \item \textbf{Fine-tuning Qwen on lecture data improves faithfulness.} The fine-tuned model (qwen7b-ft) achieves the highest ROUGE-L (0.234) and a 6.9\% relative improvement in NLI entailment over the base model, confirming that domain adaptation benefits even large LLMs.
    \item \textbf{Context window size matters more than fine-tuning domain.} All four encoder--decoder models---fine-tuned on news, books, dialogues, and academic papers respectively---perform poorly because chunking fragments the lecture content. Qwen's 128K-token window avoids this entirely.
    \item \textbf{The 6\% output ratio maximizes ROUGE-L.} Across six ratios (1--30\%), 6\% achieves the best ROUGE-L (0.233). The 1\% ratio achieves the best BERTScore and NLI entailment but at the cost of coverage.
\end{enumerate}

\section{Error Analysis}
\label{sec:errors}

We inspect model outputs across all four experiments and identify five recurring failure modes.

\paragraph{1. Chunk Fragmentation (All Four Encoder--Decoder Models).}
BART-CNN and BART-SAMSum process inputs in chunks of 1,024 tokens, while Long-T5 and LED-arXiv use 16,384-token chunks. When a lecture spans tens of thousands of tokens, even the larger-context models must split the input. This causes three problems: (i)~cross-slide arguments are split across chunks, so the model never sees the full reasoning; (ii)~each chunk summary repeats setup context, creating redundant phrasing; (iii)~the concatenated output reads as disconnected paragraphs rather than a coherent summary. The \textit{final} strategy was designed to address this by running a second summarization pass, but as shown in Figure~\ref{fig:ablation}, it usually makes things worse---BART-final produces only 50 words on average, losing content without improving coherence.

\paragraph{2. Fine-Tuning Domain Mismatch.}
Each encoder--decoder model was fine-tuned on a different domain, and none of these domains match lecture transcripts:
\begin{itemize}
    \item \textbf{BART-CNN} (news, ROUGE-L: 0.051): Produces journalistic-style summaries that miss technical definitions and formulas.
    \item \textbf{Long-T5} (books, ROUGE-L: 0.081): Generates narrative prose that lacks the structured format students expect.
    \item \textbf{BART-SAMSum} (dialogues, ROUGE-L: 0.053): Despite lectures being partially conversational, its dialogue-focused training does not help---lecture ``dialogue'' is fundamentally different from chat.
    \item \textbf{LED-arXiv} (academic papers, ROUGE-L: 0.070): The closest domain match, yet it achieves the worst BERTScore ($-$0.544). Its abstract-like style does not match lecture summary conventions.
\end{itemize}
This mismatch is visible in Figure~\ref{fig:all_nli}: BART-SAMSum has the lowest NLI entailment (0.109--0.121), even below the random baseline.

\paragraph{3. Redundancy at High Output Ratios.}
When Qwen's output ratio is set to 30\%, summaries average 2,606 words and ROUGE-L drops to 0.157 (from 0.233 at 6\%). As shown in Figure~\ref{fig:ratio_curve}, all three metrics degrade at high ratios. Manual inspection reveals repeated definitions---for example, one 30\% summary restates the definition of word embeddings three times. The extra length dilutes the density of relevant content.

\paragraph{4. High Contradiction Rates Across All Models.}
The NLI evaluation reveals high contradiction ratios across all models. Among encoder--decoder models, contradiction ranges from 37\% (LED-arXiv final) to 55\% (BART concat). Notably, Qwen models also have high contradiction ratios (79--86\%), as do TF-IDF (79\%) and Naive first-5 (70\%). This suggests the contradiction metric is partly inflated by the NLI model's 512-token limit: a summary sentence that synthesizes information from multiple parts of the lecture may appear to contradict any single short excerpt. The high contradiction for extractive methods (which copy verbatim) confirms this limitation.

\paragraph{5. BERTScore--Entailment Trade-off.}
An interesting pattern emerges from the Qwen ratio sweep (Figure~\ref{fig:ratio_curve}): BERTScore and NLI entailment peak at 1\%, while ROUGE-L peaks at 6\%. Very short summaries (176 words at 1\%) are semantically precise and well-grounded but lack coverage. Longer summaries (606 words at 6\%) cover more topics but sacrifice precision. No single ratio optimizes all metrics simultaneously, suggesting that the optimal setting depends on the application---exam review favors coverage (6\%), while fact-checking favors precision (1\%).

\section{Conclusion}
\label{sec:conclusion}

We presented StudyLens, a system for automatically summarizing university lectures by combining slide decks, transcripts, and student notes. We conducted a systematic evaluation of nine models spanning three paradigms---extractive baselines (Naive, TF-IDF), four fine-tuned encoder--decoder models (BART-CNN, Long-T5, BART-SAMSum, LED-arXiv), and instruction-tuned LLMs (Qwen2.5-7B base and fine-tuned)---across 10 lecture topics using ROUGE-L, BERTScore, and NLI factual consistency.

Our experiments yield four main conclusions:
\begin{enumerate}
    \item \textbf{LLMs outperform all other approaches.} Qwen2.5-7B achieves the best ROUGE-L (0.233 at 6\%), which is 1.4$\times$ higher than TF-IDF (0.165), 2.9$\times$ higher than Long-T5 (0.081), and 4.6$\times$ higher than BART-CNN (0.051). It is also the only model with a positive BERTScore (0.030 at 1\%).
    \item \textbf{Fine-tuning Qwen on lecture data helps.} The fine-tuned model (qwen7b-ft) achieves the highest ROUGE-L overall (0.234) and a 6.9\% relative improvement in NLI entailment (0.201 vs.\ 0.188), confirming that even large LLMs benefit from domain-specific adaptation.
    \item \textbf{Context window is more important than fine-tuning domain.} None of the four encoder--decoder models---fine-tuned on news, books, dialogues, and academic papers---produce adequate lecture summaries. Their small context windows (1K--16K tokens) force chunking that fragments cross-slide coherence, which no amount of domain-specific fine-tuning can overcome.
    \item \textbf{The optimal output ratio depends on the use case.} The 6\% ratio maximizes ROUGE-L (coverage), while 1\% maximizes BERTScore and NLI entailment (precision and faithfulness). For general lecture review, we recommend the 6--9\% range ($\sim$600 words).
\end{enumerate}

Despite strong results, factual consistency remains a challenge. Contradiction ratios are high across all models---including extractive methods that copy source text verbatim---suggesting that part of this is an artifact of the NLI evaluation's 512-token context limit rather than actual model errors. Future work should explore grounding mechanisms such as retrieval-augmented generation and should evaluate with human judges to complement automatic metrics.

Our study has several limitations. The evaluation covers 10 topics from a single institution. Reference summaries were written by one annotator per topic. The NLI cross-encoder model has a 512-token window that may undercount entailment for synthesis-heavy summaries.

Based on our findings, we recommend three practices for lecture summarization:
\begin{enumerate}
    \item Use full-context LLMs (128K+ tokens) to process entire lectures without chunking.
    \item Fine-tune on lecture-specific data when possible---even modest adaptation yields gains in faithfulness.
    \item Set the output ratio between 6\% and 9\% for balanced summaries, or 1--3\% for high-precision outputs.
\end{enumerate}
